# AI駆動開発は「クラウド環境」で動かそう：安全・並列・どこからでも

## はじめに

前回は、Claude Codeのエージェント基盤を非開発の仕事に広げるClaude Coworkを紹介しました。開発でもそれ以外でも、AIに任せる時間が長くなるほど、次に気になってくるのが「**AIがどこで動いているのか**」という点です。

ローカルで動かしている限り、作業中はPCを閉じられません。**.env** などの秘密情報はAIが読める場所に置かれたままです。一度に走らせられるタスクも、基本的には1つだけです。

本記事では、AIコーディングエージェントの作業場所を**クラウド上の隔離環境**に移す「クラウド開発環境」の考え方と、Claude Codeでの始め方を紹介します。

## クラウド開発環境とは

**クラウド開発環境**とは、エージェントがGitHubリポジトリをクローンした**隔離されたVM（仮想マシン）の中で作業し、結果をPR（プルリクエスト）として返す**仕組みです。

ポイントは「エディタがクラウドにある」ことではありません。**エージェントの作業場所そのものが、自分のPCから切り離されている**ことです。

構成要素はシンプルです。

- 隔離VM：セッションごとに用意される作業場所。自分のPCのファイルや秘密情報とは分離されます
- 環境定義：ネットワーク範囲・環境変数・セットアップスクリプトの設定。チームで共有できます
- 資格情報プロキシ：GitHubトークンなどをVMに入れず、サーバ側で付与する仕組みです
- GitHub連携：リポジトリの取得と、ブランチ・PRとしての結果の返却を担います

なお、Claude Codeの「Remote Control」は自分のPCで動くセッションを遠隔操作する機能で、実行場所はPCのままです。クラウド開発環境とは別物なので注意してください。

## クラウドを選ぶ4つの理由

### 安全性：構造でsecretsを見せない

以前の記事で紹介した **lethal trifecta**（機密データへのアクセス・信頼できない入力・外部への通信）を思い出してください。クラウド環境は、この3点のうち2つを**構造で**弱められます。

- 隔離VMで動くので、自分のPCにある秘密情報に手が届きません
- ネットワークの許可リストで、外部通信の範囲を絞れます
- GitHubトークンやAPIキーはVMに入らず、プロキシが付与します

「AIが読める場所にsecretsが無い」状態を、心がけではなく**環境の仕組み**で実現できるのが最大のメリットです。

### 並列性：PCを閉じても続く、複数同時

セッションがPCから独立しているため、PCを閉じても処理は続きます。修正Aとドキュメント更新Bを同時に走らせる、といった使い方もできます。

### 再現性：環境をコードとして定義する

必要なツールや設定を環境定義として保存しておけば、毎回同じ環境から始められます。「自分のPCでだけ動く」問題が起きにくくなります。

### 端末非依存：どこからでも同じセッションへ

ブラウザ・モバイル・デスクトップ・CLIのどこからでも同じセッションを開けます。出先ではスマホで進捗を確認し、戻ったらPCでレビューする、といった流れが自然にできます。

## それでもローカルが向く場面

もちろん、何でもクラウドが正解というわけではありません。次のような場面ではローカルが向いています。

- ローカルにしかないツール・実機・GUIを使うとき
- VMのリソース上限を超える大規模ビルドや重い処理
- 計画モードで細かく往復しながら設計を探るとき
- GitHub以外でリポジトリをホスティングしているとき

判断の型は「**クラウドを既定、ローカルを例外**」です。まずクラウドでできるかを考え、上に当てはまるときだけローカルを選びます。

## Claude Codeで始めてみよう

### 前提

クラウドセッションはPro / Max / Team、およびEnterpriseの対象シートで利用できます。GitHubとの接続が必須で、Web上の案内に従ってClaude GitHub Appを認可するか、ターミナルで **/web-setup** を実行して接続します。

### 始め方

起点は複数あり、どこから始めても同じクラウド環境を使います。

- ブラウザ（claude.ai/code）：プロンプト欄から環境を選んで開始
- モバイル：Claudeアプリの「Code」タブから
- デスクトップアプリ：セッション開始時に **Cloud** を選択
- CLI：**claude --cloud "指示"** で新規セッションを作成

最初は用意されている **Default** 環境で、小さなタスクを1件動かしてみるのがおすすめです。

### 「ローカルで計画、クラウドで実行」

複雑なタスクは、計画と実行を分けると安定します。

```bash
# 1. ローカルで計画モードに入り、方針を固める
claude --permission-mode plan

# 2. 計画をリポジトリに保存してpushする（クラウドはリモートをクローンするため）
git add docs/plan.md && git commit -m "Add plan" && git push

# 3. クラウドで実行する（複数を並列に投げられる）
claude --cloud "docs/plan.mdの計画を実行して"
```

クラウドは基本的にリモートのブランチをクローンするので、**投げる前にpushしておく**のを忘れないようにしましょう。

## 環境を整える：最低限の設定

環境は「設定ダイアログ」から調整できます。まず押さえたいのは次の3点です。

### ネットワークアクセス

**None / Trusted / Full / Custom** の4段階から選びます。既定の **Trusted** は、パッケージレジストリやGitHubなど一般的な開発に必要な範囲だけを許可します。許可外のホストへの通信は拒否されるため、自社APIなどが必要なときだけ **Custom** で追加します。

### 環境変数とsecrets

環境変数は、環境を使う全員が値を読めます。**トークンやAPIキーは環境変数に置かない**でください。ProやMaxでは、キーをVMに入れずプロキシが付与する **API credentials** が使えます。

### セットアップスクリプトとSessionStartフック

足りないツールは、セットアップスクリプト（Claude起動前にrootで実行されるBashスクリプト）で追加できます。結果は一定期間キャッシュされ、次回以降の起動が速くなります。

プロジェクト依存の導入（npm installなど）は、リポジトリの **.claude/settings.json** にSessionStartフックとして書くのが定番です。クラウドでのみ実行したいときは、環境変数 **CLAUDE_CODE_REMOTE** が true かどうかで分岐します。

```bash
#!/bin/bash
# scripts/install_pkgs.sh — クラウドでのみ依存を導入する
set -euo pipefail
if [ "${CLAUDE_CODE_REMOTE:-}" != "true" ]; then
  exit 0
fi
npm ci
```

また、一定時間アイドルが続くとVMは回収され、再開時には未pushのファイルは戻りません。**こまめにcommit & pushする**習慣をつけておくと安心です。

## 他のツールでも同じ考え方

ここではClaude Codeを例にしましたが、OpenAI Codex、GitHub Copilotのコーディングエージェント、Cursor、Google Julesなども、基本構造は同じです。「クラウドの隔離環境で動き、結果をPRで返す」という考え方が分かっていれば、ツールが変わっても応用できます。

なお、プラン条件や画面の名称は変更されることがあります。設定する際は[Claude Codeの公式ドキュメント](https://code.claude.com/docs/en/claude-code-on-the-web)で最新情報を確認してください。

## まとめ

要点を3つにまとめます。

- クラウド開発環境は、エージェントの作業場所を**自分のPCから切り離した隔離VM**に移す仕組みです
- 利点は**安全性・並列性・再現性・端末非依存**の4つ。特にsecretsを構造的に見せない点が大きな強みです
- 判断の型は「**クラウドを既定、ローカルを例外**」。計画はローカル、実行はクラウドという分担も有効です

次のアクションとして、まずは小さな修正タスクを1件、クラウドセッションに投げてみてください。PCを閉じても作業が進む感覚を一度体験すると、ローカルに戻れなくなるかもしれません。
